# Балесноландия — ВлодБанк, Касса, ВлодУслуги

Игровая экономика вымышленной Балесноландской Федерации (БФ): три связанных веб-приложения и общая админка.

> Игровой сервис. Не является банком, госорганом, платёжным средством или удостоверением личности.

Целевой адрес сайта: `https://bln.vladislavb.qzz.io` (Cloudflare Pages после настройки); API остаётся на VPS: `https://vps.vladislavb.qzz.io`. Подготовка репозитория сама по себе сайт не публикует.

| Приложение | Адрес | Что внутри |
| --- | --- | --- |
| ВлодУслуги | `/services/` | Паспорт БФ (ID-карта, QR, печать 58 мм), ИНН, ИП, права, загранпаспорт и визы, брак и рождение, квитанции, налоги и декларации, штрафы и обжалования, пособия, имущество, врач и страховка, выборы, обращения, новости БФ, рабочие места госслужащих, проверка документов по QR |
| ВлодБанк | `/bank/` | Счета (расчётный, накопительный, вклад, бизнес), дебетовые и кредитные карты, переводы, оплата квитанций и QR, госуслуги и налоги, покупка имущества с ипотекой и автокредитом, банкомат, операционист |
| Касса | `/pos/` | Магазины, склад и закупки, акции и баллы, варианты и добавки, долги, столики и счета, кухня и очередь, киоск, отчёты, смены X/Z, терминал покупателя, чек PNG 58 мм, возвраты |
| Админка | `/admin/` | Банк, Экономика, Касса, Услуги (штрафы, санкции, имущество, страны и визы, выборы, новости, госбюджет, налоги, пособия и зарплаты, ипотека и страховка), Люди, Система |

## Что сделано

Сделаны этапы 1–8 из ТЗ. Сверх этого готова установка как PWA.

- **Фундамент.** MySQL/MariaDB-миграции. Журнал проводок с двойной записью: блокировка строк `SELECT … FOR UPDATE`, ключи идемпотентности, проверка «сумма всех счетов = 0». Вход по паролю и по коду на email (6 цифр, 10 минут, 5 попыток). JWT в httpOnly cookie, автовыход по бездействию. WebSocket-каналы `user:`, `terminal:`, `shop:`, `admin`, `clock`. Ограничение частоты запросов на вход, коды и PIN. Темы светлая/тёмная, языки ru/it, бургер-меню на маленьких экранах, дисклеймер на каждой странице, в письмах, на картах, чеках и документах.
- **ВлодУслуги.** Аккаунт, паспорт БФ (автовыдача или одобрение — переключатель в админке), ИНН, ИП с госпошлиной через квитанцию, подтверждение связки с ВлодБанком, проверка по QR.
- **ВлодБанк.** Регистрация с паспортом, вход через ВлодУслуги, стартовый баланс из эмиссии. Счета, карты (12 цифр, PIN из 3 цифр, QR и штрихкод, 3 неверных PIN — заморозка на 1 минуту, заморозка, смена PIN, лимиты, перевыпуск, фон). Переводы по карте, счёту, имени и между своими счетами с комиссией. Банкомат. Рабочее место операциониста: выдача карт, наличные, инкассация.
- **Касса.** Цепочка ИП → бизнес-счёт → магазин, персонал с PIN кассира и зарплатой, каталог с фото и штрихкодом, штучные и весовые товары, варианты и добавки, остатки, сканер камерой, удаление и восстановление товаров без потери истории продаж. Отложенные чеки, ручная скидка, акции и промокоды, скидка за количество, баллы лояльности, чаевые 0/5/10/15 %, проверка возраста по QR паспорта, раздельная оплата и продажа в долг. Терминал покупателя по коду сопряжения, экран «Отказано» со звуком, экран «Нет связи с сервером». НДС отдельной строкой: с безнала уходит в бюджет сразу, с наличных и долгов — при Z-отчёте. Возвраты целиком и частями тем же способом, приём квитанций наличными, журнал действий, звуки кассы.
- **Админка.** Настройки и ставки, роли, очередь заявок, эмиссия и изъятие с журналом, отмена операций (сторно), блокировки и арест счетов, экономика, игровое время (пауза, «следующий месяц»), реестр граждан, экспорт, импорт и полный сброс JSON (админы сохраняются).

- **Этап 6 — игровое время и финансы.**
  - *Кредитная карта:* заявка на лимит, лимит одобряет админ. Льготный период без процентов, затем процент в месяц на долг. Каждый месяц — выписка с минимальным платежом (по желанию автопогашение с основного счёта), за пропуск — штраф и падение рейтинга.
  - *Кредиты:* аннуитетный график, автосписание платежа каждый игровой месяц, пени за просрочку, досрочное погашение. Небольшие кредиты админ может разрешить одобрять автоматически. Долг виден на ссудном счёте.
  - *Кредитный рейтинг* 0…1000: растёт за платежи вовремя, падает за просрочки.
  - *Детская карта:* счёт родителя, держатель — ребёнок (если у него есть аккаунт, карта видна и ему), лимиты, история, карманные с автостартом.
  - *Подарочная карта:* тратится на кассе или зачисляется на любой счёт по номеру и PIN.
  - *Автоплатежи и подписки:* каждый игровой месяц, после 3 неудач — пауза.
  - *Кешбэк:* клиент выбирает категории на месяц (у магазина категория в настройках кассы), начисление за оплату картой и по QR, возврат покупки его уменьшает, выплата — в начале следующего месяца с лимитом.
  - *Антифрод:* крупные, необычные и слишком частые переводы ждут решения админа. Крупные оплаты картой, по QR и снятия проходят, но попадают на проверку: при отказе — сторно и заморозка карты.
  - *Инфляция:* индекс цен растёт на ставку админа каждый игровой месяц; по нему дорожают оптовые цены.
  - *Обслуживание карт* — плата в игровой месяц.
  - Всё настраивается в админке: «Банк → Кредиты / Антифрод / Кешбэк / Ставки кредитов», «Экономика → Инфляция».

- **Этап 7 — касса, расширение.**
  - *Склад и закупки.* У каждого товара — закупочная цена, остаток, отправка на кухню, оптовая цена для других магазинов. Приход и списание вручную, журнал движений склада, предупреждение о низком остатке. Закупка на оптовой базе админа списывает деньги с бизнес-счёта и сразу приходует товар по средневзвешенной себестоимости; цены базы растут вместе с индексом инфляции. Заказ у другого магазина ждёт подтверждения продавца: при принятии деньги, товар и остатки двигаются одной транзакцией, при отказе — ничего не меняется.
  - *Скидки и лояльность.* Ручная скидка, акции (процент от чека, сумма, процент за количество от N штук), промокоды с лимитом использований и минимальной суммой. Баллы магазина: процент от чека, ограничение доли чека, начисление за оплату картой и QR, списание на кассе, возврат баллов при отмене и возврате.
  - *Долги.* «Тетрадь долгов» магазина: продажа в долг на имя должника, погашение наличными в ящик или картой на бизнес-счёт. Если покупатель — клиент ВлодБанка, долг появляется у него в кабинете (раздел «Долги») и гасится с любого счёта; списание безнадёжного долга — только владелец.
  - *Столики и счета (кафе).* Карта зала, открытый счёт на столе, добавление блюд, отправка на кухню, перенос счёта на другой стол, закрытие и оплата любым способом; отмена оплаты возвращает счёт на стол.
  - *Кухня и очередь.* Экран кухни «новый → готовится → готов → выдан» с проверкой переходов и звуком нового заказа. Публичное табло очереди открывается без входа на любом экране в зале.
  - *Киоск самообслуживания.* Витрина без кассира, оплата только картой или по QR, номер заказа и чек; выход и возврат на кассу — по PIN сотрудника, простой возвращает витрину.
  - *Отчёты владельцу.* Выручка, прибыль после НДС и закупочной стоимости, средний чек, НДС, скидки, возвраты, чаевые, графики по дням и часам, категории, способы оплаты, источники продаж, топ товаров, по кассирам, закупки, долги, стоимость склада и остатки к закупке.
  - *Админка и банк.* В админке — «Касса → Оптовая база» с индексом инфляции и историей цен, список закупок всех магазинов. В ВлодБанке — раздел «Долги» с погашением в один клик.

- **Этап 8 — ВлодУслуги, расширение.**
  - *Налоги и декларации.* НДС и НДФЛ удерживаются автоматически. ИП раз в игровой год подаёт декларацию: доход подставляется по выручке касс, меньше указать нельзя, налог уходит в квитанцию. Налог на имущество начисляется владельцам каждый игровой год. Ставки и сроки — в админке «Услуги → Налоги».
  - *Штрафы и обжалования.* Полицейский в рабочем месте проверяет гражданина по паспорту, видит документы, машины, действующие меры и штрафы; выписывает по статье из списка или свободно, со своей суммой. Гражданин видит штраф и квитанцию, обжалует в течение срока, админ удовлетворяет или отклоняет жалобу. Пока жалоба рассматривается, квитанция заморожена и пени не растут.
  - *Неуплата.* Каждый игровой месяц — пени процентом от долга; затем арест счетов в ВлодБанке (деньги за долг списываются автоматически, если их хватает), запрет выезда (нет загранпаспорта и визы) и закрытие ИП с закрытием магазинов. Меры снимаются автоматически после полной оплаты.
  - *Пособия.* Детское (за каждого ребёнка из паспорта), пенсия (по возрасту) и пособие по безработице (не работать и не иметь ИП), на счёт ВлодБанка. Заявку одобряет чиновник, выплаты идут из госбюджета каждый игровой месяц.
  - *Имущество.* Реестр авто и недвижимости: админ добавляет лоты, в том числе государственные на продажу. Купля-продажа между гражданами и у государства, оплата через ВлодБанк, ипотека и автокредит с первым взносом и залогом до погашения, продать заложенное нельзя.
  - *Врач и страховка.* Врач публикует слоты на приём, в том числе приоритетные — только для застрахованных. Пациент записывается (не больше трёх записей), пишет жалобу, получает игровое заключение. Полис покупается квитанцией.
  - *Выборы.* Админ создаёт голосование, проходит этапы выдвижения, голосования и завершения; кандидата можно не допустить. Один паспорт — один голос, голос тайный (связь избирателя с кандидатом не хранится), итоги публикуются в новостях БФ.
  - *Визы и документы.* Водительские права, загранпаспорт, визы в страны из списка (сбор и срок задаёт админ), свидетельства о браке и о рождении — через заявление, госпошлину и рассмотрение. Безвизовые страны указаны отдельно.
  - *Обращения и новости.* Гражданин пишет обращение в администрацию, полицию, налоговую, врачу или чиновнику; сотрудник отвечает из рабочего места, автор получает уведомление. Админ публикует новости, указы, законы и закрепляет их.
  - *Госбюджет.* Админ видит остаток, доходы и расходы по видам (НДС, квитанции, НДФЛ, пособия, зарплаты, продажа госимущества), график по дням и дебиторку. Зарплаты госслужащих платятся из бюджета с удержанием НДФЛ.
  - *Рабочие места.* В ВлодУслугах — «Работа» для чиновника, полицейского, налогового инспектора и врача: очередь обращений, проверка граждан и штрафы, декларации и должники с доначислением налога, расписание приёма и заключения, заявки на пособия.

Осталось по ТЗ — этап 9: Web Push, письма-уведомления, PDF-документы, звуки, PWA-статистика экономики с графиками.

## Устройство

```
shared/   валюта (влодики/влодинки, сдача по купюрам, НДС), игровое время, форматы номеров — общие для API и фронтенда
api/      Node.js 20 + Fastify + MySQL/MariaDB + WebSocket; src/routes/* — REST /api, src/lib/* — логика, src/migrations/*.sql
web/      React + Vite, multi-page: index (выбор приложения), bank/, pos/, services/, admin/; src/shared — UI-кит, i18n, печать 58 мм
```

Принципы:

- **Деньги — только на сервере.** Все суммы — целые влодинки (`BIGINT`). Любое движение денег — проводка в `ledger_entries`, сумма которой по операции равна 0. Баланс кешируется в `accounts.balance`, его сверка видна в админке.
- **Служебные счета:** «Эмиссия» (уходит в минус), «Казна ВлодБанка», «Госбюджет БФ», «Наличные в обороте».
- **Маршрутизация по hash** (`#/accounts/5`). Каждое приложение имеет собственный `index.html`; специальные правила перенаправления на хостинге не нужны.

## Запуск локально

Нужны Node.js 20.19+ и MySQL 8 или MariaDB 10.5+.

```bash
npm install
```

```bash
cp api/.env.example api/.env   # для разработки: NODE_ENV=development, DB_*, MAIL_TRANSPORT=console, ADMIN_EMAILS=ваш@email
```

```bash
npm run migrate
```

```bash
npm run dev:api
```

```bash
npm run dev:web
```

Откройте http://localhost:5173/. Vite проксирует `/api` и `/ws` на API (порт 3100). При `MAIL_TRANSPORT=console` письма с кодами печатаются в лог API.

Первый админ: зарегистрируйтесь во ВлодУслугах или ВлодБанке с email из `ADMIN_EMAILS` — роль `admin` выдаётся автоматически. Или выдайте её вручную:

```bash
npm run make-admin -w api -- you@example.com gov
```

Проверки:

```bash
npm run lint
```

```bash
npm test
```

API-тесты используют отдельную базу `bln_test` (имя меняется через `TEST_DB_NAME`) и полностью её пересоздают. Тесты интерфейса — на Vitest и jsdom: `npm test -w web` (или `npm run test:web`), они проверяют, что страницы этапа 8 рисуются на реальных формах ответов API.

## Деплой

Фронтенд и API публикуются независимо:

- `.github/workflows/deploy-frontend.yml` собирает статический фронтенд и загружает его в **Cloudflare Pages** при изменениях сайта в `main`. Адрес API и WebSocket указываются при сборке; этот workflow не меняет и не перезапускает VPS.
- `.github/workflows/deploy.yml` сохраняет существующую FTP-публикацию **только API**. В `main` она автоматически запускается при изменениях `api/` или `shared/`; при изменениях одного фронтенда не запускается.

Пошаговая настройка Cloudflare Pages, GitHub Actions, домена, CORS, проверка и откат: **[docs/cloudflare-pages.md](docs/cloudflare-pages.md)**. Публикация и изменение DNS выполняются только после настройки владельцем проекта.

API по-прежнему применяет миграции при запуске, хранит секрет подписи в базе и перезапускается при обновлении файла `VERSION`. Существующие FTP-доступы и настройки базы для API остаются в окружении `production`. Важно: переменные `SITE_DOMAIN` и `API_DOMAIN` этого окружения, если они заданы, переопределяют новые адреса по умолчанию. Изменения одного корневого `package-lock.json`, влияющие на API, требуют отдельного ручного запуска деплоя API.

Адреса сайта, дополнительные origin для CORS и SMTP также настраиваются в админке **Система → Адреса и почта** без перезапуска. SMTP-пароль хранится в базе и не попадает в экспорт JSON.

Если в журнале хостинга видно падение на старте с `ERR_SYSTEM_ERROR: uv_interface_addresses returned Unknown system error 97` — это контейнер, который не отдаёт список сетевых интерфейсов. Fastify читает его только ради строки с адресами при прослушивании `0.0.0.0`, а ошибка вылетает уже после открытия порта. API обходит это (`api/src/lib/netinfo.js`): пишет одно предупреждение и продолжает работать. Падение в журнале от старой сборки лечится повторной выкладкой API.

| Вопрос | Решение |
| --- | --- |
| Поддомен API | `vps.vladislavb.qzz.io` и фронтенд `bln.vladislavb.qzz.io` — один сайт для `SameSite` cookie при HTTPS, но разные origin; нужен CORS с credentials |
