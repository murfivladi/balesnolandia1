# Балесноландия — ВлодБанк, Касса, ВлодУслуги

Игровая экономика вымышленной Балесноландской Федерации (БФ): три связанных веб-приложения и общая админка.

> Игровой сервис. Не является банком, госорганом, платёжным средством или удостоверением личности.

Целевой адрес сайта: `https://bln.vladislavb.qzz.io` (Cloudflare Pages после настройки); API остаётся на VPS: `https://vps.vladislavb.qzz.io`. Подготовка репозитория сама по себе сайт не публикует.

| Приложение | Адрес | Что внутри |
| --- | --- | --- |
| ВлодУслуги | `/services/` | Паспорт БФ (ID-карта, QR, печать 58 мм), ИНН, ИП, квитанции, связка с банком, проверка паспорта/чека/документа по QR, рассмотрение заявлений |
| ВлодБанк | `/bank/` | Счета (расчётный, накопительный, вклад, бизнес), дебетовые карты, переводы, оплата квитанций и QR, банкомат, операционист |
| Касса | `/pos/` | Магазины, товары, смены X/Z, продажа (наличные со сдачей по купюрам, карта, QR, раздельная), терминал покупателя, чек PNG 58 мм, возвраты |
| Админка | `/admin/` | Банк, Экономика, Касса, Услуги, Люди, Система |

## Что сделано

Сделаны этапы 1–6 из ТЗ. Сверх этого готова установка как PWA.

- **Фундамент.** MySQL/MariaDB-миграции. Журнал проводок с двойной записью: блокировка строк `SELECT … FOR UPDATE`, ключи идемпотентности, проверка «сумма всех счетов = 0». Вход по паролю и по коду на email (6 цифр, 10 минут, 5 попыток). JWT в httpOnly cookie, автовыход по бездействию. WebSocket-каналы `user:`, `terminal:`, `shop:`, `admin`, `clock`. Ограничение частоты запросов на вход, коды и PIN. Темы светлая/тёмная, языки ru/it, дисклеймер на каждой странице, в письмах, на картах, чеках и документах.
- **ВлодУслуги.** Аккаунт, паспорт БФ (автовыдача или одобрение — переключатель в админке), ИНН, ИП с госпошлиной через квитанцию, подтверждение связки с ВлодБанком, проверка по QR.
- **ВлодБанк.** Регистрация с паспортом, вход через ВлодУслуги, стартовый баланс из эмиссии. Счета, карты (12 цифр, PIN из 3 цифр, QR и штрихкод, 3 неверных PIN — заморозка на 1 минуту, заморозка, смена PIN, лимиты, перевыпуск, фон). Переводы по карте, счёту, имени и между своими счетами с комиссией. Банкомат. Рабочее место операциониста: выдача карт, наличные, инкассация.
- **Касса.** Цепочка ИП → бизнес-счёт → магазин, персонал с PIN кассира и зарплатой, каталог с фото и штрихкодом, штучные и весовые товары, остатки, сканер камерой. Отложенные чеки, ручная скидка, чаевые 0/5/10/15 %, проверка возраста по QR паспорта, раздельная оплата. Терминал покупателя по коду сопряжения, экран «Отказано» со звуком, экран «Нет связи с сервером». НДС отдельной строкой: с безнала уходит в бюджет сразу, с наличных — при Z-отчёте. Возвраты целиком и частями тем же способом, приём квитанций наличными, журнал действий, отчёты владельцу, звуки кассы.
- **Админка.** Настройки и ставки, роли, очередь заявок, эмиссия и изъятие с журналом, отмена операций (сторно), блокировки и арест счетов, экономика, игровое время (пауза, «следующий месяц»), реестр граждан, экспорт, импорт и полный сброс JSON (админы сохраняются).

- **Этап 6 — игровое время и финансы.**
  - *Кредитная карта:* заявка на лимит, лимит одобряет админ. Льготный период без процентов, затем процент в месяц на долг. Каждый месяц — выписка с минимальным платежом (по желанию автопогашение с основного счёта), за пропуск — штраф и падение рейтинга.
  - *Кредиты:* аннуитетный график, автосписание платежа каждый игровой месяц, пени за просрочку, досрочное погашение. Небольшие кредиты админ может разрешить одобрять автоматически. Долг виден на ссудном счёте.
  - *Кредитный рейтинг* 0…1000: растёт за платежи вовремя, падает за просрочки.
  - *Детская карта:* счёт родителя, держатель — ребёнок (если у него есть аккаунт, карта видна и ему), лимиты, история, карманные с автостартом.
  - *Подарочная карта:* тратится на кассе или зачисляется на любой счёт по номеру и PIN.
  - *Автоплатежи и подписки:* каждый игровой месяц, после 3 неудач — пауза.
  - *Кешбэк:* клиент выбирает категории на месяц (у магазина категория в настройках кассы), начисление за оплату картой и по QR, возврат покупки его уменьшает, выплата — в начале следующего месяца с лимитом.
  - *Антифрод:* крупные, необычные и слишком частые переводы ждут решения админа. Крупные оплаты картой, по QR и снятия проходят, но попадают на проверку: при отказе — сторно и заморозка карты.
  - *Инфляция:* индекс цен растёт на ставку админа каждый игровой месяц; по нему будут дорожать оптовые цены (этап 7).
  - *Обслуживание карт* — плата в игровой месяц.
  - Всё настраивается в админке: «Банк → Кредиты / Антифрод / Кешбэк / Ставки кредитов», «Экономика → Инфляция».

Остальное — по этапам 7–9 из ТЗ: склад и оптовая база, кухня, очередь, киоск, налоги, штрафы, имущество (ипотека и автокредит), выборы, врач, Web Push, PDF-выписки и договоры. Таблицы и маршруты для них добавляются отдельными миграциями (`api/src/migrations/006_…`).

## Устройство

```
shared/   валюта (влодики/влодинки, сдача по купюрам, НДС), игровое время, форматы номеров — общие для API и фронтенда
api/      Node.js 20 + Fastify + MySQL/MariaDB + WebSocket; src/routes/* — REST /api, src/lib/* — логика, src/migrations/*.sql
web/      React + Vite, multi-page: index (выбор приложения), bank/, pos/, services/, admin/; src/shared — UI-кит, i18n, печать 58 мм
```

Принципы:

- **Деньги — только на сервере.** Все суммы — целые влодинки (`BIGINT`). Любое движение денег — проводка в `ledger_entries`, сумма которой по операции равна 0. Баланс кешируется в `accounts.balance`, его сверка видна в админке.
- **Служебные счета:** «Эмиссия» (уходит в минус), «Казна ВлодБанка», «Госбюджет БФ», «Наличные в обороте».
- **Маршрутизация по hash** (`#/accounts/5`). Каждое приложение имеет собственный `index.html`; специальные правила перенаправления на хостинге не нужны.

## Запуск локально

Нужны Node.js 20.19+ и MySQL 8 или MariaDB 10.5+.

```bash
npm install
```

```bash
cp api/.env.example api/.env   # для разработки: NODE_ENV=development, DB_*, MAIL_TRANSPORT=console, ADMIN_EMAILS=ваш@email
```

```bash
npm run migrate
```

```bash
npm run dev:api
```

```bash
npm run dev:web
```

Откройте http://localhost:5173/. Vite проксирует `/api` и `/ws` на API (порт 3100). При `MAIL_TRANSPORT=console` письма с кодами печатаются в лог API.

Первый админ: зарегистрируйтесь во ВлодУслугах или ВлодБанке с email из `ADMIN_EMAILS` — роль `admin` выдаётся автоматически. Или выдайте её вручную:

```bash
npm run make-admin -w api -- you@example.com gov
```

Проверки:

```bash
npm run lint
```

```bash
npm test
```

API-тесты используют отдельную базу `bln_test` (имя меняется через `TEST_DB_NAME`) и полностью её пересоздают.

## Деплой

Фронтенд и API публикуются независимо:

- `.github/workflows/deploy-frontend.yml` собирает статический фронтенд и загружает его в **Cloudflare Pages** при изменениях сайта в `main`. Адрес API и WebSocket указываются при сборке; этот workflow не меняет и не перезапускает VPS.
- `.github/workflows/deploy.yml` сохраняет существующую FTP-публикацию **только API**. В `main` она автоматически запускается при изменениях `api/` или `shared/`; при изменениях одного фронтенда не запускается.

Пошаговая настройка Cloudflare Pages, GitHub Actions, домена, CORS, проверка и откат: **[docs/cloudflare-pages.md](docs/cloudflare-pages.md)**. Публикация и изменение DNS выполняются только после настройки владельцем проекта.

API по-прежнему применяет миграции при запуске, хранит секрет подписи в базе и перезапускается при обновлении файла `VERSION`. Существующие FTP-доступы и настройки базы для API остаются в окружении `production`. Важно: переменные `SITE_DOMAIN` и `API_DOMAIN` этого окружения, если они заданы, переопределяют новые адреса по умолчанию. Изменения одного корневого `package-lock.json`, влияющие на API, требуют отдельного ручного запуска деплоя API.

Адреса сайта, дополнительные origin для CORS и SMTP также настраиваются в админке **Система → Адреса и почта** без перезапуска. SMTP-пароль хранится в базе и не попадает в экспорт JSON.
