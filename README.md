# Балесноландия — ВлодБанк, Касса, ВлодУслуги

Игровая экономика вымышленной Балесноландской Федерации (БФ): три связанных веб-приложения и общая админка.

> Игровой сервис. Не является банком, госорганом, платёжным средством или удостоверением личности.

| Приложение | Адрес | Что внутри |
| --- | --- | --- |
| ВлодУслуги | `/balesnolandia/services/` | Паспорт БФ (ID-карта, QR, печать 58 мм), ИНН, ИП, квитанции, связка с банком, проверка паспорта/чека/документа по QR, рассмотрение заявлений |
| ВлодБанк | `/balesnolandia/bank/` | Счета (расчётный, накопительный, вклад, бизнес), дебетовые карты, переводы, оплата квитанций и QR, банкомат, операционист |
| Касса | `/balesnolandia/pos/` | Магазины, товары, смены X/Z, продажа (наличные со сдачей по купюрам, карта, QR, раздельная), терминал покупателя, чек PNG 58 мм, возвраты |
| Админка | `/balesnolandia/admin/` | Банк, Экономика, Касса, Услуги, Люди, Система |

## Что сделано

Сделаны этапы 1–5 из ТЗ — после них уже можно играть. Сверх этого готовы игровой таймер с процентами, вкладами, сроками карт и зарплатами кассиров, а также установка как PWA.

- **Фундамент.** MySQL/MariaDB-миграции. Журнал проводок с двойной записью: блокировка строк `SELECT … FOR UPDATE`, ключи идемпотентности, проверка «сумма всех счетов = 0». Вход по паролю и по коду на email (6 цифр, 10 минут, 5 попыток). JWT в httpOnly cookie, автовыход по бездействию. WebSocket-каналы `user:`, `terminal:`, `shop:`, `admin`, `clock`. Ограничение частоты запросов на вход, коды и PIN. Темы светлая/тёмная, языки ru/it, дисклеймер на каждой странице, в письмах, на картах, чеках и документах.
- **ВлодУслуги.** Аккаунт, паспорт БФ (автовыдача или одобрение — переключатель в админке), ИНН, ИП с госпошлиной через квитанцию, подтверждение связки с ВлодБанком, проверка по QR.
- **ВлодБанк.** Регистрация с паспортом, вход через ВлодУслуги, стартовый баланс из эмиссии. Счета, карты (12 цифр, PIN из 3 цифр, QR и штрихкод, 3 неверных PIN — заморозка на 1 минуту, заморозка, смена PIN, лимиты, перевыпуск, фон). Переводы по карте, счёту, имени и между своими счетами с комиссией. Банкомат. Рабочее место операциониста: выдача карт, наличные, инкассация.
- **Касса.** Цепочка ИП → бизнес-счёт → магазин, персонал с PIN кассира и зарплатой, каталог с фото и штрихкодом, штучные и весовые товары, остатки, сканер камерой. Отложенные чеки, ручная скидка, чаевые 0/5/10/15 %, проверка возраста по QR паспорта, раздельная оплата. Терминал покупателя по коду сопряжения, экран «Отказано» со звуком, экран «Нет связи с сервером». НДС отдельной строкой: с безнала уходит в бюджет сразу, с наличных — при Z-отчёте. Возвраты целиком и частями тем же способом, приём квитанций наличными, журнал действий, отчёты владельцу, звуки кассы.
- **Админка.** Настройки и ставки, роли, очередь заявок, эмиссия и изъятие с журналом, отмена операций (сторно), блокировки и арест счетов, экономика, игровое время (пауза, «следующий месяц»), реестр граждан, экспорт, импорт и полный сброс JSON (админы сохраняются).

Остальное — по этапам 6–9 из ТЗ: кредитные, детские и подарочные карты, кредиты, автоплатежи, кешбэк, антифрод, инфляция, склад и оптовая база, кухня, очередь, киоск, налоги, штрафы, имущество, выборы, врач, Web Push, PDF-выписки. Таблицы и маршруты для них добавляются отдельными миграциями (`api/src/migrations/005_…`).

## Устройство

```
shared/   валюта (влодики/влодинки, сдача по купюрам, НДС), игровое время, форматы номеров — общие для API и фронтенда
api/      Node.js 20 + Fastify + MySQL/MariaDB + WebSocket; src/routes/* — REST /api, src/lib/* — логика, src/migrations/*.sql
web/      React + Vite, multi-page: index (выбор приложения), bank/, pos/, services/, admin/; src/shared — UI-кит, i18n, печать 58 мм
```

Принципы:

- **Деньги — только на сервере.** Все суммы — целые влодинки (`BIGINT`). Любое движение денег — проводка в `ledger_entries`, сумма которой по операции равна 0. Баланс кешируется в `accounts.balance`, его сверка видна в админке.
- **Служебные счета:** «Эмиссия» (уходит в минус), «Казна ВлодБанка», «Госбюджет БФ», «Наличные в обороте».
- **Маршрутизация по hash** (`#/accounts/5`). Поэтому `.htaccess` на хостинге не нужен; приложенный `web/public/.htaccess` только настраивает кеширование.

## Запуск локально

Нужны Node.js 20.19+ и MySQL 8 или MariaDB 10.5+.

```bash
npm install
```

```bash
cp api/.env.example api/.env   # пропишите DB_*, MAIL_TRANSPORT=console, ADMIN_EMAILS=ваш@email
```

```bash
npm run migrate
```

```bash
npm run dev:api
```

```bash
npm run dev:web
```

Откройте http://localhost:5173/balesnolandia/. Vite проксирует `/api` и `/ws` на API (порт 3100). При `MAIL_TRANSPORT=console` письма с кодами печатаются в лог API.

Первый админ: зарегистрируйтесь во ВлодУслугах или ВлодБанке с email из `ADMIN_EMAILS` — роль `admin` выдаётся автоматически. Или выдайте её вручную:

```bash
npm run make-admin -w api -- you@example.com gov
```

Проверки:

```bash
npm run lint
```

```bash
npm test
```

API-тесты используют отдельную базу `bln_test` (имя меняется через `TEST_DB_NAME`) и полностью её пересоздают.

## Деплой

`push` в `main` запускает `.github/workflows/deploy.yml`: тесты → сборка фронтенда → FTP на shared hosting → rsync API на VPS → `npm ci` → миграции → `pm2 startOrReload`.

Секреты репозитория (Settings → Secrets → Actions, окружение `production`):

| Секрет | Пример |
| --- | --- |
| `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD` | доступ к shared hosting |
| `FTP_DIR` | `/public_html/balesnolandia/` (со слешем в конце) |
| `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY` | SSH-доступ к VPS (приватный ключ целиком) |
| `VPS_APP_DIR` | `/srv/balesnolandia` |
| `API_URL` | `https://api.vladinc.ru` |
| `WS_URL` | `wss://api.vladinc.ru/ws` |

Подготовка VPS (один раз):

1. Установите Node.js 20, MariaDB или MySQL, nginx, `npm i -g pm2`, затем `pm2 startup`.
2. Создайте базу и пользователя: `CREATE DATABASE balesnolandia CHARACTER SET utf8mb4;`
3. Создайте `$VPS_APP_DIR/api/.env` по образцу `api/.env.example`: пароли базы и SMTP, `JWT_SECRET` (`openssl rand -hex 32`), `COOKIE_DOMAIN=.vladinc.ru`, `CORS_ORIGINS=https://vladinc.ru`, `MAIL_FROM`.
4. Настройте nginx по `docs/nginx-api.conf` и выпустите сертификат: `certbot --nginx -d api.vladinc.ru`.
5. API работает **одним процессом**: WebSocket-шина и игровой таймер живут в памяти.

## Открытые вопросы из ТЗ — что выбрано

| Вопрос | Решение |
| --- | --- |
| Поддомен API | По умолчанию `api.vladinc.ru`; cookie ставятся на `.vladinc.ru`, CORS с credentials. Вариант через прокси `vladinc.ru/balesnolandia/api` тоже работает: задайте `API_URL` и `WS_URL` |
| `.htaccess` на shared hosting | Не обязателен: маршруты на `#/…`. Если поддерживается — включится кеширование статики |
| Версия MySQL / MariaDB | Схема проверена на MariaDB 10.11 и совместима с MySQL 8; JSON-столбцы читаются в обоих вариантах |
| Адрес писем | `MAIL_FROM` в `.env` (по умолчанию `no-reply@vladinc.ru`) |
